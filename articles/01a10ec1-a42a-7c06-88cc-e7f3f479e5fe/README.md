## OSS開発において周辺資源の管理コストは下げるべき

小規模なチームでOSSを運営するにあたって、管理するものを減らす戦略が必要です。結果として、オープンな開発環境および資源を採用することや、マネージドサービスを薄く使うことが合理的な選択になります。

具体的には、自社インフラよりAWS、AWS上にCIを組むよりGitHub Actionsを選択し、既定値をベースとした宣言的で明示的な管理を優先することが挙げられます。たしかにセルフホストは最も柔軟で、既存資産があるなら一見低コストです。しかし、チームの注意力が有限で高価なリソースであることは見逃される傾向があります。GitHub Actionsはプロプライエタリですが、独自の便利機能を排除して`npm test`だけにまとめたワークフローなら過度なロックインの懸念は杞憂であり、管理コストの最小化の観点からも、そのように薄く使うべきです。

また、こうしたチームにおいて、プロプライエタリフォントを採用するのは厄介です。もちろん技術的には、OSSであることはプロプライエタリフォントの採用を妨げません。一方で、CIインフラは複雑になり、ライセンスや支払いの管理が求められます。アウトライン化した静的アセットを作成するだけだとしても、フォントファイルの管理は外せません。これらは管理対象を減らす要求と衝突します。別の観点では、ブランディングのために手配した高価なフォントが、むしろブランディングの散逸を誘発します。ほとんどの利用者はプロプライエタリフォントへのアクセスを持たず、代替フォントを使います。代替フォントであふれると、ブランドは希薄化します。ロゴであっても、絵というより文字として識別するものは、文字として記述されうる前提でOSS書体をベースにしたほうがよいでしょう。誰でも無償で再現できる書体は、そのじつ、ブランドを守る低コストで強固な仕組みになるのです。
